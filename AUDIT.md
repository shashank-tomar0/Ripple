# Ripple Reality Audit

> **What this is:** a living ledger of every subsystem in Ripple, what it
> actually does, and how its behavior is **proven** — not claimed.
>
> **The rule:** nothing on screen or in the background may be fake. A feature
> exists only if it is backed by code that runs, a test that asserts, or a
> measured fact. Anything that doesn't meet that bar is listed below as
> **NOT REAL** until it does. This file is the contract.
>
> **Status legend:** 🟢 proven · 🟡 real code, proof gap · ⚫ not built

## 1. Go daemon (`go-daemon`)

### 1.1 Identity & keys — 🟢
Ed25519 keypair generated on first run, persisted as PEM (`identity.go`),
peer ID derived from public key. **Proof:** `identity.Verify()` sign/verify
round-trip; exercised on every daemon start; CI builds and tests.

### 1.1b Identity backup (BIP39 seed phrase) — 🟢
The 32-byte Ed25519 seed is encoded as a standard 24-word BIP39 mnemonic
(`mnemonic.go`); the same phrase on any device recreates the exact same
keypair and PeerID. `rippled -export-seed` prints the phrase,
`rippled -import-seed "…"` restores it; the bridge serves it to the app
as a request/response `seed_export` frame (never broadcast — it is the
private key material). **Proof:** `mnemonic_test.go` — round-trip,
determinism, the published Trezor BIP39 vectors (16- and 32-byte), invalid
phrase rejection (bad checksum, unknown words, wrong length); integration
test Phase C restores node1's identity in a fresh directory and asserts
the byte-identical phrase re-exports, and Phase D asserts the bridge
serves the exact same phrase as the CLI.

### 1.2 E2E encryption — 🟢
NaCl box (X25519 + XSalsa20-Poly1305) per-peer keys, key exchange messages,
message encrypt/decrypt, key persistence (`crypto/box.go`). **Proof:**
`box_test.go` covers key generation, import/export, exchange, encrypt/decrypt
round-trips. A real self-deadlock was found and fixed here.

### 1.3 Message envelope & codec — 🟢
JSON wire envelope (id, type, sender, recipient, payload, nanos timestamp,
TTL, hop count, nonce, key id) plus a binary codec (`codec/codec.go`).
**Proof:** `message_test.go`, `codec_test.go`; nanos timestamps are asserted
in Flutter unit tests too.

### 1.4 Store — 🟡
In-memory message store with optional JSON backup persistence.
**Honest status:** this is NOT a database. No SQLite (README no longer claims
it). **Proof:** `store_test.go` (in-memory + JSON round-trip).
**Gap:** crash-durable, queryable storage is a product milestone (Phase 5).

### 1.5 Mesh (libp2p) — 🟢
TCP transport, mDNS discovery, GossipSub pubsub, direct streams, store-and-
forward relay with TTL and dedup. **Proof:** the CI integration test runs
3 real `rippled` processes and asserts actual delivery between them.

### 1.6 Relay event stream — 🟢
Every message passing through a node emits a typed event: `sent`,
`received`, `forwarded`, `dropped` (TTL expired or duplicate), with the
relaying peer, hop count, TTL and timestamp. **Proof:** `relay_test.go`
asserts the exact event sequences; the integration test runs a linear
3-node chain (node1↔node2↔node3, mDNS off — node1 and node3 never
connected) and asserts node2's bridge emits `received`+`forwarded` for the
only message path that can reach node3.

### 1.7 WebSocket bridge — 🟢
Typed frames: identity, chat, file, sos, delivery_ack, key_exchange,
seed_export, peer_join/leave, relay, ping/pong, error. Server-side
enforcement of sender identity (clients cannot spoof the peer ID).
**Proof:** used by the CI integration test (send + listen + seed probes).

### 1.8 Delivery receipts — 🟢
Received-acks are generated by the mesh node (`delivery_ack`) and surfaced
to the app over the bridge. **Proof:** integration test Phase B sends a DM
from node1 to node3 (a peer node1 cannot dial directly), which is routed
through node2, auto-acked by node3, and the `received` receipt is asserted
back at node1's bridge. **Note:** an old `delivery` package claiming retry
logic was dead code (never wired in) — deleted. Automatic re-send on
failure is Phase 3 store-and-forward work, tracked below.

### 1.9 File transfer — 🟡
Metadata/progress/complete messages exist in both halves; `filetransfer`
manager exists. **Proof gap:** no end-to-end file transfer test with real
chunks. Not claimed as working until it is.

### 1.10 SOS — 🟡
Broadcast SOS with urgency, location, expiry; manager + bridge + app banner
exist. **Proof gap:** no end-to-end SOS delivery test.

## 2. Flutter app (`flutter-app`)

### 2.1 Daemon transport — 🟢
`WebSocketDaemonService` is the default; it speaks the real bridge protocol.
**Proof:** analyze-clean, unit-tested models, APK builds in CI; protocol is
the same one the integration test exercises.
**Remaining proof gap:** the app has never been run against a live daemon on
a device/emulator (no emulator in this environment). First manual milestone.

### 2.2 State layer — 🟢
`AppState` derives peers from real join/leave events and conversations from
the local message cache. No canned data. **Proof:** code-reviewed; CI compiles.

### 2.3 Mesh map — 🟡
Live topology from real peer events; **message-hop animation fed by real
relay events from the daemon** (no synthetic traffic): dots travel from the
relaying peer to you on `received`, rings radiate on `forwarded`, red blips
on `dropped`, plus a live one-line audit ticker. **Proof:** the daemon side
is proven by integration assertions; the widget compiles in CI; visual
proof requires the device smoke test.

### 2.4 QR contact exchange — 🟡
QR display/scan exist; scanning records the contact locally from the
scanned URI (peer ID, nickname, public key) and sends a real
`key_exchange` message through the daemon (was a no-op TODO that showed a
fake "Connected!" snackbar). The UI reports honestly whether the key
exchange was sent. **Proof:** bridge-side send path compiles and is
exercisable; end-to-end proof requires the device smoke test.

### 2.5 Fake-data mode — ⚫ **DELETED**
`LocalDaemonService` (which invented contacts, replies, and receipts) is
gone, along with the `LOCAL_DEMO` flag and the stub `getPeers()`/
`getConversations()`/`getMessages()` list methods that returned empty
lists. If the daemon is unreachable, the app shows a disconnected state —
it never invents data. No fake mode ships.

### 2.6 Timestamps — 🟢
Single wire convention: Unix **nanoseconds** everywhere, via
`utils/time.dart` (`unixNanosNow`). Flutter unit tests assert conversion.
